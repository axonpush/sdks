# Shared contract

This SDK is not hand-written against the API from memory. It is generated from
a single source of truth, `contract/openapi.sdk.json`, which the axonpush
server produces from its Huma (Go) OpenAPI spec and mirrors into this repo. All
three SDKs (TypeScript, Python, .NET) share that one contract, which is why
they stay in lockstep.

## Where the contract comes from

`contract/openapi.sdk.json` is generated by the server and arrives here as a
pull request. Do not hand-edit it. `contract/spec.lock` records the server
commit it was cut from:

```json
{ "source": "axonpush/server", "sha": "…", "ref": "master", "workflow": "…" }
```

Alongside it:

- `contract/operations.txt` lists every published operation.
- `contract/unwrapped.txt` lists operations that intentionally have no
  hand-written resource method, each with a reason (ingest surfaces called by a
  wire protocol or exporter, infrastructure the client reaches through its own
  code paths, or known gaps to wrap later).
- `contract/fixtures/` pins the parts of the contract OpenAPI cannot carry:
  the webhook HMAC scheme, canonical header names (`X-API-Key` for `ak_` keys,
  `X-Public-Token` for `pt_` public ingest tokens, `x-tenant-id`, the
  `X-Axonpush-*` scoping and tracing headers), and the `AXONPUSH_*`
  configuration surface with units. Each SDK replays these as conformance tests
  (`src/__tests__/contract.test.ts`) so the timeout unit, the fail-open
  default, and the retry ladder cannot drift between languages.

## How codegen works

The generated client layer under `src/_internal/api` is produced by
[`@hey-api/openapi-ts`](https://heyapi.dev/) from `contract/openapi.sdk.json`
(see `openapi-ts.config.ts`). It is checked in but off limits: change the
server, let the contract follow, then regenerate.

```bash
mise run codegen        # regenerate every client from contract/ (no backend needed)
# or, for just this package:
bun run codegen
```

`bun run codegen` runs `@hey-api/openapi-ts` and then
`tools/postprocess-generated.ts`. The generated code produces the typed
operations in `sdk.gen.ts` and their types in `types.gen.ts`. Everything a
user touches is the hand-written layer on top:

- **Resource classes** (`src/resources/*`) wrap the generated operations
  behind an ergonomic surface (`client.events.publish(...)`).
- **The transport chokepoint** (`src/_internal/transport.ts`) owns auth
  headers, tenancy, environment scoping, trace propagation, retries with the
  contract's backoff ladder, and fail-open semantics. It routes `ak_` keys to
  `X-API-Key` and `pt_` public ingest tokens to `X-Public-Token`.
- **Framework integrations** (`src/integrations/*`) and the **error tree**
  (`src/errors.ts`) map the backend's `{ code, message, hint, requestId }`
  envelope onto typed errors.

## Rules of the road

1. Never hand-edit `contract/` or `src/_internal/api`.
2. A new server endpoint must be wrapped in a resource method or listed in
   `contract/unwrapped.txt` with a reason.
3. Keep the hand-written surface mirrored across languages; the surface-diff
   tool at the repo root compares them.
